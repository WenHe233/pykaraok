# 以往项目的做法和用户反馈

这些项目的模板源文件都在 examples/ 下，可以直接复制来改。

## 共通的工作方式

- **先理解歌词和画面**，再定主题：草莓果酱、ED 画面的水彩晕染、冰晶融化、三人演唱的舞台色。用户评价效果时只看画面，“好看优先”。
- **按句规划图层**：先列出一句里有哪些元素（光晕、本体、高光、粒子、背景笔触），各占哪一层，再写模板。写进 `--@note`，方便以后修改。
- **时间**：
  - 入场在句首之前 200 到 400 ms 开始；
  - 退场要在本句结束前完成，`code line` 看不到下一句；
  - 句与句之间没有空档时，上一句退完、下一句再进。
- **参数集中**：颜色、时长、开关集中放在一行“配置” code once 里，用户在 Aegisub 里改完点 Apply 就能生效。
- **随机值由行决定**（`px.rand`），重新套用时结果完全一致。
- **每次修改另存新版本**，不覆盖旧版。

## 草莓果酱（kimishinu_12_IN 插入曲，examples/strawberry_jam）

- 整句只有开头一个 `{\k1}`，逐字效果用 `template char`。
- 每句的草莓和第一个字同时落地，中文在同一时刻弹出，角落的果酱罐随歌词涨高，最后一句盖上格子布。“罐子行”放在最后，读取前面每句的时间。
- 用户反馈：
  - “效果还是不够漂亮……好看优先”，于是重做了 v2，旧版保留。
  - “草莓落进罐子和字幕出现不太同步”，差了约 0.3 秒，要逐帧对齐画面事件。
  - “日语字号小，中文字号大”。
- 缺字（気、別）用本字体的部件拼出，没有换字体。

## 水彩晕染（kimishinu_07 ED，examples/watercolor）

- 要求：“不要动我的歌词位置和字体样式”。静止阶段要与原行逐像素一致，所以用 `px.layout.geom` 精确定位，并用 `check --steady` 验证。
- 用户反馈：
  - “有时候字会突然错位乱飘一帧”：碰撞挪动，加 `px.still` 解决。
  - “能看出几个水彩的圈”：椭圆叠加的边缘太规则，改为分形噪声取等值线（`px.noise`）。
  - “更像是一层描边”：模糊字形做的晕染像描边，改成独立的噪声笔触。
  - “水彩一直保留到行消失”：做了常驻版。
  - “参考原视频的颗粒感”：颗粒用程序生成的绘图，注意每帧耗时。
- 水彩颜色按 ED 画面分段，写在 `wc.scenes` 表里，按绝对时间取色。

## 冰晶融化（rrk-ass，examples/ice_melt）

- 未唱的字是冰晶：冰蓝填充、斜向晶面高光、蓝边。唱到时白光一闪，晶面消失，转为暖白加淡粉边。长音时字底凝出水滴落下，退场时字向下融化。
- 尾句单独处理，按开始时间判断，不向下融化，改为化作星光上升。
- 图层分配：1 光晕，2 本体，3 高光，4 唱到时的光晕，5 入场扫光，6 水滴，7 星光。

## 舞台合唱（alma Live《A·I》，examples/live_chorus）

- 三位演唱者用 `\3c` 标记，合唱行（说话人为“合唱”）按舞台站位做彩虹渐变描边，并按 165 BPM 缓慢流动。拍点从音频测得，现在用 `pykaraok beats`。
- 关键词有专属特效：故障、扫描线、爱心、进度条、鼠标点击。
- 背景歌词（JP 小、CN 小）的垂直边距是用户手调的，不能改。
- 中文行借用对应日文行的发声时间，所以日文行要排在中文行之前。

## 卡拉 OK OP（ass-test，阿尔玛 OP）

- 用户规则：
  - 日文同一时刻只显示一句；
  - 中文只做整句效果，不做伪逐字；
  - 句间空档不小于 0.86 秒时才做半透明预告。
- 用户提供了自己打的 k 轴，替换了从音频推导的时间。这件事浪费了一个多小时，以后不要从音频推导 `\k`。
- 画面里的日文 logo 汉化：中文放在原 logo 上方，一到两行，不遮盖原文；出现、故障、消失按源视频逐帧对齐。这些行的 Effect 写 `logo`，重新套用时不会被删。
