# libass 渲染上的坑

都是以往项目里真实遇到过的。

## 位置

- **碰撞挪动**：时间重叠、又没有 `\pos`、`\move`、`\org`、`\t` 的行，libass 会把后一行挤到别处（`\fade` 不算）。表现为字幕突然错位一帧，或者两句上下叠成两行。处理：fx 行都写 `\pos` 或 `\move`；必须靠边距定位的行加 `px.still`。用 `check` 的 collisions 和 jumps 检查。
- **绘图按包围盒对齐**：`\p` 图形按坐标的包围盒 [0, W] x [0, H] 对齐，坐标出现负数时整体偏移。几块图形要叠在一起对齐时，给每块加同一个 `m 0 0 m W H` 前缀（`px.shape.boxed`）。
- **同一行里的多段绘图会依次排开**，不会叠在一起。要叠加就拆成多行。
- **逐字放置要精确到 1/64 px**：要与原行重合时，用 `px.layout.geom`，它按 libass 的 lrint 取整（.5 取偶）。
- `\an5` 的绘图在部分情况下位置不对。改用 `\an7` 加左上角坐标更可靠。

## 描边、透明、缩放

- `\bord` 不随 `\fscx`/`\fscy` 缩放。放大字时，描边相对变细。
- `\1a&HFF&`（填充全透明）时，描边内部会被挖空，只剩外圈。想要“只有光晕”的层，用较大的 `\bord` 加 `\blur`，再配 `\3a`。
- 同一属性的多个 `\t` 要首尾相接，不要重叠，否则后一个会覆盖前一个。
- `\t(\clip(...))` 可以用于扫光或擦除。

## 字体与字宽

- libass 用 HarfBuzz 排版，带字距调整（kerning）；Aegisub 的 text_extents（GDI）不带。拉丁字母混排时，逐音节摆放的位置和整行渲染会有小偏差。静止阶段要求逐像素一致时，用 `check --steady` 验证。
- 字体缺字时会换字体，宽度也跟着变，导致其后所有字的位置偏移（见 fonts.md）。

## 性能

- 每帧预算：24 fps 约 41 ms，30 fps 约 33 ms（`render perf` 或 `check --perf`）。
- 很多小字或小图形做成的颗粒纹理很贵：07 项目里一版颗粒每帧 54 ms，被放弃了。
- 大半径 `\blur` 加大面积描边的成本最高。

## 渲染器差异

- 用户交付只保证 libass（mpv、ffmpeg 压制、MPC-HC 的 libass 模式）。
- 用户的 Aegisub 预览器配置可能是 xy-VSFilter。分层绘图在 VSFilter 下会错位，要提醒用户在 Aegisub 里切到 libass 才能看到正确效果。
